# lesson-47 · 11-4 합의 규칙과 포크

## 목표
- 소프트포크와 하드포크를 규칙 집합의 관계로 정의한다.
- 업그레이드하지 않은 노드 관점에서 두 포크를 설명한다.
- 블록 크기 논쟁과 SegWit 활성화, 체인 분리의 경과를 사실 중심으로 설명한다.

| | 소프트포크 | 하드포크 |
|---|---|---|
| 규칙 변화 | 강화 (유효했던 것 일부를 무효로) | 완화 (무효였던 것 일부를 유효로) |
| 새 규칙 블록을 구 노드가 보면 | 유효 (구 규칙도 만족) | 무효 (구 규칙 위반) |
| 구 노드의 처지 | 업그레이드 안 해도 같은 체인 (검증 범위는 줄어듦) | 업그레이드하지 않으면 다른 체인에 남음 |
| 예 | P2SH, SegWit, Taproot | 블록 크기 한도 증가 시도들 |

연표 (s114-timeline): 2010 1MB 한도 → 2015 상향 논쟁 → 2017 상반기 SegWit 시그널링 교착(95% 기준) → 2017년 5월 SegWit + 2MB 하드포크 묶음안 → 2017년 8월 1일 UASF(BIP148) 시한, 같은 날 블록 478,558 이후 분리 → 비트코인캐시 → 8월 24일 블록 481,824에서 SegWit 활성화 → 11월 2MB 계획 취소.

## 파일
- `fork_points.sh` — 메인넷 풀노드가 있을 때 01·04 단계를 노드로 확인 (없으면 탐색기만으로 충분)

## 실습 순서 (s114-lab, 공개 블록 탐색기로 — 노드 없이 가능)
1. 비트코인 탐색기에서 블록 478,558과 478,559를 조회한다.
2. 비트코인캐시 탐색기에서 같은 높이를 조회한다 → 478,559부터 블록 해시가 다르다(장부가 둘로 갈린 순간).
3. 분리 이전 코인은 두 체인 모두에 존재 → 한쪽 트랜잭션이 다른 쪽에서도 유효하게 재생되는 "리플레이" 문제와 방지 장치를 정리한다.
4. 비트코인 블록 481,824 전후를 조회해 witness가 있는 트랜잭션이 처음 나타나는 모습을 확인한다. 탐색기마다 화면이 달라 찾기 어려우면 트랜잭션 상세나 원시 데이터 보기를 연다.

메인넷 풀노드가 있을 때: 01은 두 높이의 블록 해시(탐색기 값과 같아야 한다), 04는 블록마다 "트랜잭션 N개, witness 있는 것 M개" 한 줄씩이다. 활성 전 블록(481,823)은 witness가 있으면 무효라 M이 0이어야 하고, 활성 블록부터 witness 트랜잭션이 나타날 수 있다. witness 커밋먼트가 있는 블록은 코인베이스에도 witness 예약값이 있어 함께 센다. 마지막 줄은 `{"type": "buried", "active": true, "height": 481824}`다(활성 높이가 코드에 고정된 buried 배포, 11-5).
