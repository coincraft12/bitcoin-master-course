# lesson-37 · 9-1 노드 발견과 연결, 일식 공격

## 목표
- 새 노드가 네트워크에 합류해 피어를 찾는 과정을 설명한다.
- 아웃바운드·인바운드·블록 전용 연결의 역할을 구분한다.
- 일식 공격의 원리와 노드의 방어 장치를 설명한다.

부트스트랩 순서 (s91-boot): 이전 주소록(peers.dat, anchors) → DNS 시드 → 하드코딩 시드 → addr 메시지로 주소 교환.

| 유형 (Core 기본값, s91-conn) | 방향 | 하는 일 | 기본 개수 |
|---|---|---|---|
| 전체 릴레이 아웃바운드 | 내가 먼저 | 트랜잭션·블록·주소 모두 교환 | 8 |
| 블록 전용 아웃바운드 | 내가 먼저 | 블록만. 구조 노출 방지, 일식 공격 저항 | 2 |
| 피일러(feeler) | 짧게 | 주소록의 주소가 살아 있는지 확인 | 수시 |
| 인바운드 | 남이 나에게 | 포트를 열어 둔 노드만 | 최대 연결 125 중 나머지 |

일식 공격 방어 (s91-eclipse): 다양성(같은 대역·AS에서 여러 개 고르지 않음) · 블록 전용 연결과 앵커 · 축출 규칙 · 버킷 단위 주소록.

## 파일
- `my_peers.py` — 실습 코드 (s91-lab). 인자로 네트워크를 바꿀 수 있고, 끝에 주소록 크기(`getnodeaddresses`)를 보탰다

## 실습 순서
1. signet(또는 메인넷) 노드가 있으면 그대로, 없으면 9-2(lesson-38)의 regtest 2노드 환경을 먼저 띄운다.
2. 방향·연결 유형·네트워크·전송 방식 분포를 연결 유형 표와 대조한다.
3. subver로 피어의 소프트웨어·버전을, 핑이 빠른 다섯 피어를 본다. 전송 방식 v1/v2는 9-3.
4. 주소록 크기를 확인한다.

포트 8333을 열면 새 노드의 부트스트랩을 돕지만 집 공유기에서는 IP가 노출된다(Tor는 9-3).

## 실행

