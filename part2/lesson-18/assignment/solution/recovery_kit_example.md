# 나의 복구 키트 — 가상의 2-of-3 멀티시그 (작성 예시)

> 연습용 예시. 키 값은 적지 않고 이름만 쓴다.

## 1. 지갑 개요
- 정책(말로): A·B·C 세 키 중 아무 둘이 서명하면 쓸 수 있다. `thresh(2,pk(A),pk(B),pk(C))`
- 디스크립터 형식: `wsh(sortedmulti(2,[fpA/48h/0h/0h/2h]xpubA/0/*,[fpB/…]xpubB/0/*,[fpC/…]xpubC/0/*))#체크섬`
  - sortedmulti: 키를 정렬하므로 참여자가 키를 어떤 순서로 적든 같은 주소가 나온다. 복구 때 순서 실수를 없앤다.
  - 잔돈용 `/1/*` 디스크립터도 함께 적는다.
- 생성 시점: 실제 생성일보다 하루 이르게 적는다 (늦게 적으면 그 전에 받은 코인을 놓친다).
- 경로: 각 키 m/48h/0h/0h/2h (멀티시그 경로는 지갑마다 다를 수 있어 디스크립터에 명시).

## 2. 무엇을 · 어디에 · 누가

| 항목 | 비밀/공개 | 보관 장소 | 보관자 | 매체 |
|---|---|---|---|---|
| 키 A 니모닉 | 비밀 | 집 금고 | 본인 | 금속 판 |
| 키 B 니모닉 | 비밀 | 은행 대여금고 | 본인 | 금속 판 |
| 키 C 니모닉 | 비밀 | 가족 집 | 배우자 | 종이 2부(봉인) |
| 전체 공개 디스크립터 (받는용·잔돈용) | 공개(프라이버시) | A·B·C 보관 장소 각각 | 각 보관자 | 종이 + 암호화 USB |
| 생성 시점·지갑 소프트웨어·버전 | 공개 | 디스크립터와 같은 봉투 | 각 보관자 | 종이 |

## 3. 점검
- [x] 세 장소 어디에나 전체 공개 디스크립터가 있다 → 어느 키 하나를 잃어도 남은 두 장소에서 주소를 재구성할 수 있다.
- [x] 한 장소에는 니모닉이 하나뿐이다 → 한 곳이 털려도 정족수(2)가 안 된다.
- [x] 사진·클라우드 보관 없음.
- [x] 복구 리허설: 1년에 한 번, 원래 기기가 아닌 다른 기기의 Core에 공개 디스크립터를 워치온리로 가져와 첫 받는 주소와 잔액을 대조. 소액으로 2-of-3 서명까지 시험.
- [x] 보관자 부재 시: 배우자가 이 문서의 위치를 안다. 문서에는 비밀 값이 없다.
