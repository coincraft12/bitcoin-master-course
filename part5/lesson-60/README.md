# lesson-60 · 14-4 제도권 편입, 과정 마무리와 최종 프로젝트

## 목표
- 현물 ETF·기업·국가 보유의 구조와 그 비트코인이 누구의 키로 잠겨 있는지 설명한다 (s144-etf, s144-holdings).
- 국내 가상자산 과세와 현물 ETF 도입 논의의 현황을 정리한다 (s144-korea).
- 제도권 편입이 네트워크 거버넌스에 주는 영향을 양면에서 설명한다 (s144-impact).

현물 ETF 구조: 발행·운용사(펀드·지분 발행), 수탁사(실제 비트코인 키 보관, 12-3의 콜드월렛 구조), 승인 참가자(설정·환매로 가격 맞춤), 투자자(펀드 지분 보유, 키·출금 권리 없음). 수탁사가 소수에 집중된다. 일부 ETF가 공개한 보유 주소는 온체인으로 확인할 수 있다(13-3 scantxoutset).

보유 주체별 규모 (2026년 10월 초 공개 추적 자료, s144-holdings): ETF·거래소 약 160만 BTC, 상장사 197개사 약 128만(최대 보유사 약 84.8만), 국가 약 65만, 비상장사 약 28만 → 2,100만 대비 ETF·거래소 약 7.6%, 상장사 약 6.1%, 국가 약 3.1%, 합계 약 17%. 추적 자료는 공시·추정 혼합이며, 이 과정은 특정 기업·국가의 전략을 평가하거나 투자 판단을 시사하지 않는다.

국내 현황 (2026년 10월 기준, s144-korea)
| 항목 | 현황 |
|---|---|
| 이용자 보호 | 가상자산이용자보호법 시행(2024년 7월) · 이용자 자산 보관 의무, 콜드월렛 80% 이상 (12-3) |
| 과세 | 2027년 1월 1일 이후 양도·대여분부터 기타소득 분리과세 · 연 250만 원 공제, 세율 22%(지방소득세 포함) · 2026년 말 이전 보유분은 2026년 12월 31일 시가와 실제 취득가액 중 큰 금액을 취득가액으로 |
| 국제 정보 교환 | OECD CARF에 따른 정보 수집이 2026년부터 |
| 현물 ETF | 정부 2026년 경제성장전략에 도입 추진 포함, 자본시장법 개정(가상자산을 ETF 기초자산에) 추진 · 수탁·가격 산정 체계는 입법 과정에서 결정 |
| 2단계 입법 | 디지털자산기본법(사업자 세분화, 스테이블코인 제도화 등) 하반기 입법 추진, 관련 법안 다수 계류 |

영향(s144-impact): 긍정 — 유동성·접근성, 법적 지위 명확화, 보안·수탁 기술 투자, 해시레이트를 지탱하는 경제 규모. 우려 — 수탁 집중으로 소수 기관이 대량의 코인 통제, 포크·정책 논쟁에서 "경제 노드"로 큰 영향력(11-4), 규제 압력이 채굴·노드 운영으로 번질 가능성, "키 없는 보유자" 증가.

과정 마무리(s14-return): "중앙 기관 없이 이중지불을 막을 수 있을까?" — UTXO(1-4) · 서명(7강) · 스크립트(6강) · 작업증명과 체인 선택(10~11강) · 정책과 합의(8강, 11강)로 답하고, 그 답을 지키는 일은 키 관리(12강) · 확장 설계(13강) · 사회적 합의(14강)까지 함께다.

## 파일
- `holdings_ratio.py` — 실습 01: 보유 주체별 표와 2,100만 대비 비율(정수 연산). 기본값은 s144-holdings 슬라이드 수치, 직접 조사한 숫자는 CSV로
- `final_project/` — 최종 프로젝트 "signet에서 Taproot 볼트 지갑 구성과 운영" (README, exercise, solution)

## 실습: 공개 데이터로 보유 구조 보기 (s144-lab)
1. 공개 추적 자료로 현물 ETF·상장사·국가 보유량을 표로 정리, 2,100만 대비 비율 계산 (11-2)
   ```bash
   python part5/lesson-60/holdings_ratio.py
   python part5/lesson-60/holdings_ratio.py 내_조사.csv      # 한 줄에 "주체,BTC"
   ```
2. 보유 주소를 공개한 ETF·기업의 주소 일부를 `scantxoutset` 또는 탐색기로 조회해 공시와 비교 (13-3)
   ```bash
   python part5/lesson-55/reserve_check.py 공개주소.txt --disclosed <공시 BTC>
   ```
   주소를 공개하지 않은 곳은 이 단계가 불가능하다는 것 자체가 정보다.
3. "이 코인들의 키는 몇 개의 기관이 쥐고 있는가"로 한 단락 정리

## 기대 출력
`holdings_ratio.py` (결정적, 직접 실행해 확인)
```
보유 주체                    BTC  2,100만 대비
ETF·거래소             1,600,000     7.6%
상장사 (197개사)       1,280,000     6.1%
국가                     650,000     3.1%
비상장사·펀드            280,000     1.3%
앞 3개 합계            3,530,000    16.8%
→ 숫자보다 "이 코인들의 키는 몇 개의 기관이 쥐고 있는가"를 한 단락으로 정리한다 (실습 03).
```
슬라이드의 "합계 약 17%"는 앞 3개(ETF·거래소, 상장사, 국가)의 합 16.8%를 반올림한 값이다. 비상장사는 합계에 넣지 않았다.

## 최종 프로젝트
`final_project/README.md` 참고. 제출물: 디스크립터(공개) · 송금 txid · 설계서 2~3쪽. 평가: 디스크립터 정확성 40% · 복구 경로 설계의 타당성 30% · 트랜잭션 구조 설명 30%. 실제 자금용 키나 니모닉은 절대 제출하지 않는다.

## 흔히 막히는 지점
