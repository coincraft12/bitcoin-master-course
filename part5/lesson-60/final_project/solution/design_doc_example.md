# 최종 프로젝트 설계서 작성 예시 — signet Taproot 볼트 지갑

네트워크: signet · Bitcoin Core 31.x · 가정: 3인 소규모 법인의 콜드월렛(12-3 볼트를 Taproot로)

> 이 예시의 키 이름은 역할 이름이다. 실제 제출물에는 `vault_wallet.sh`가 남긴 공개 디스크립터와 txid를 넣는다. 개인키·니모닉은 넣지 않는다.

## 1. 제출물
- 공개 디스크립터: `tr([지문/86h/1h/0h]tpub…/0/*,{multi_a(2,K1/0/*,K2/0/*,K3/0/*),and_v(v:pk(R/0/*),older(52560))})#체크섬` 과 잔돈용 `/1/*` 한 줄
- 송금 txid: 키 경로 1건, 2-of-3 리프 1건 (경로를 함께 적는다)

## 2. 위협 모델
| 지킬 것 | 공격자 | 경로 | 대응 |
|---|---|---|---|
| 평시 서명 키 | 원격 해커 | 키 유출 | 키 경로 키는 하드웨어 지갑, 2-of-3 리프가 대체 경로 |
| 서명 권한 | 내부자 | 단독 인출 | 리프는 2-of-3 정족수 (MuSig2 키 경로면 키 경로도 2인) |
| 핵심 인력 | (사고·퇴사) | 키 보유자 부재 | 2-of-3 중 1명 부재 허용, 장기 부재는 복구 리프 |
| 디스크립터 | (분실) | 주소 재구성 불가 | 디스크립터 사본을 모든 키 장소에 (4-5) |

## 3. 키 보관 계획
| 키 | 역할 | 보관자 | 장소 | 장비 |
|---|---|---|---|---|
| 키 경로 | 평시 지출 (단일 서명처럼 보임) | 대표 | 본사 금고 | 제조사 X |
| K1 | 리프 2-of-3 | 대표 | 본사 금고 | 제조사 Y |
| K2 | 리프 2-of-3 | 재무 담당 | 다른 도시 | 제조사 Z |
| K3 | 리프 2-of-3 | 외부 수탁 파트너 | 제3의 장소 | 종이 백업 |
| R | 복구 리프 | 변호사 사무실 | 대여금고 | 종이 백업 |

## 4. 리프 배치 이유
- 평시 지출은 키 경로 → witness가 서명 64바이트 하나뿐이라 수수료가 가장 작고, 체인에서 일반 단일 서명 송금과 구분되지 않는다(6-4).
- 2-of-3 리프와 복구 리프를 깊이 1에 나란히: 어느 쪽을 써도 컨트롤 블록 65바이트(1 + 내부키 32 + 형제 리프 해시 32). 쓰지 않은 리프는 해시 32바이트로만 남는다(6-5).
- 단일 키 키 경로의 약점: 그 키 하나가 털리면 단독 인출. 그래서 금액이 크면 키 경로를 `musig(K1,K2)`로(평시에도 2인 서명, Core 31 지갑 지원) 바꾸는 것을 권한다 — 대신 두 사람이 2라운드로 서명해야 한다.

## 5. 복구 절차
- N = 52,560블록(약 1년). 상한 65,535 안에서, 정상 운영 중에는 열리지 않을 만큼 길게.
- 리프레시: 6개월마다 볼트 자기 주소로 재송금(재무 담당, 달력 반복 일정). 잊으면 복구 리프가 열린 상태가 된다.
- 복구: (1) 디스크립터 사본으로 워치온리 지갑 복원 (2) 입금 확정 뒤 N블록 경과 확인 (3) `walletcreatefundedpsbt`에 입력 `sequence: N` 지정 (4) R 지갑이 서명 (5) 완성·전파. regtest에서 `OLDER=20`으로 매년 리허설.

## 6. 트랜잭션 구조 설명
| 경로 | witness (바이트) | 설명 |
|---|---|---|
| 키 경로 | [64] | 조정된 출력키에 대한 Schnorr 서명 하나 (SIGHASH_DEFAULT라 65가 아니라 64) |
| 2-of-3 리프 (K1+K3) | [64, 0, 64, 104, 65] | 스택 아래부터 K3 서명, K2 자리 빈 값, K1 서명, 리프 스크립트, 컨트롤 블록 |
| 복구 리프 | [64, 37, 65] (N=20) | R 서명, `<R> CHECKSIGVERIFY <N> CSV`, 컨트롤 블록. 입력 nSequence = N |

리프 스크립트 104바이트 = `<K1> CHECKSIG <K2> CHECKSIGADD <K3> CHECKSIGADD OP_2 OP_NUMEQUAL`. CHECKSIGADD는 서명이 맞으면 카운터에 1을 더하고, 빈 값이면 그대로 둔다(7-4, BIP342).
PSBT 역할: 워치온리 볼트 지갑이 Creator·Updater(리프 스크립트와 각 키의 파생 경로를 채운다), 각 키 지갑이 Signer, `combinepsbt`가 Combiner, `finalizepsbt`가 Finalizer·Extractor.
