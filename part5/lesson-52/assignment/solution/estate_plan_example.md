# 우리 집 상속·복구 설계 (작성 예시 · 가상의 가족)

작성일: 2026-10 · 다음 점검일: 2027-04 (6개월마다)

> 등장하는 키는 모두 이름으로만 부른다. 실제 니모닉·확장 개인키·패스프레이즈·주소는 이 문서 어디에도 없다.

가정: 본인(40대), 배우자, 미성년 자녀 1명. 비트코인은 본인이 단독 관리. 배우자는 기술에 익숙하지 않다.

## 01 위협 모델 요약 (12-1)
| 지킬 것 (자산) | 노리는 쪽 (공격자) | 경로 | 대응 |
|---|---|---|---|
| 본인 키 시드 | 원격 해커, 악성 앱 | 키 유출, 피싱 | 하드웨어 지갑, 시드는 종이·금속에만 |
| 서명 권한 | 사기꾼 | 주소 중독, 변조 PSBT | 주소록 전체 대조, 서명 기기 화면 확인 (12-2 체크리스트) |
| 보유 사실 | 물리적 강요자 | 노출 → 가정 침입 | 보유 사실 비공개, 큰 금액은 즉시 인출 불가 구조 |
| 상속 가능성 | (사고·질병) | 본인 부재 → 영구 손실 | 아래 02의 타임락 복구 경로 |

## 02 복구 경로 정책 (12-4)
- miniscript 정책: `or(pk(본인),and(pk(배우자),older(52560)))`
- N = 52,560블록 (약 1년). 이유: 본인이 장기 입원 등으로 몇 달 움직이지 못해도 가족 경로가 열리지 않을 만큼 길고, 상한 65,535블록(약 15개월) 안에 든다. 가족이 1년 남짓 기다리는 것은 감당 가능하다고 판단했다.
- 구현: Taproot로 본인 키 = 내부키(키 경로), 배우자 조건 = 스크립트 리프. 평시 지출이 단일 서명과 구분되지 않는다 (6-4, 6-5). 쓰는 지갑 소프트웨어가 이 리프로 서명·완성할 수 있는지 리허설로 확인한다 (s124-patterns 주의점).

## 03 리프레시와 상속 문서
- 리프레시 주기: 6개월마다 자기 자신에게 재송금 (N의 절반). 담당: 본인. 알림: 달력 반복 일정 + 점검일에 배우자와 함께 확인.
- 상속 문서 목차 — 넣을 것:
  1. 비트코인 자산이 있다는 사실과 대략적 위치(어느 지갑 소프트웨어, 어느 기기)
  2. 공개 디스크립터 사본과 사용한 지갑 소프트웨어 이름
  3. 단계별 복구 안내서 (배우자 키로 1년 후 지출하는 순서, 화면 캡처 포함)
  4. 연락할 사람: 기술 도움을 줄 지인 1명, 전문가 1곳
  5. 백업 장소 목록 (내용이 아니라 위치만: "은행 대여금고", "본가 금고")
- 넣지 말 것:
  1. 니모닉·개인키 원문 (본인 키, 배우자 키 모두)
  2. 패스프레이즈 (별도 경로로 전달)
  3. 모든 비밀을 한 문서에 모으는 것. 유언장에는 비밀을 넣지 않는다 (집행 전 열람 위험)
