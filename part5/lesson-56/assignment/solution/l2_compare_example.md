# L2 비교표 작성 예시 — 라이트닝 vs Liquid

> 이 예시는 **강의 슬라이드(13-3, 13-4)에 나온 사실만** 썼다. 실제 과제에서는 Liquid 공식 문서·공지로 각 칸을 확인하고 확인일을 적는다. 슬라이드에 없는 내용은 "공식 문서로 확인"으로 남겨 두었다 — 수강생이 채울 부분이다.

고른 L2: Liquid (페더레이션 사이드체인) · 기준: 2026년 9월 중순까지의 강의 자료

| 질문 | 라이트닝 | Liquid |
|---|---|---|
| 1. 출금 강제력 | 상대 비협조 시 강제 종료로 온체인 정산 | 페그아웃은 페더레이션이 처리하며 승인된 회원 지갑으로만 나간다(PAK). 페더레이션이 협조하지 않을 때 사용자가 스스로 BTC를 되찾는 절차는 슬라이드에 없음 → 공식 문서로 확인. 2026년 9월 중순 기준 페그인·아웃 중단 |
| 2. 자금 통제 | 채널 양 당사자 (2-of-2) | 여러 기관이 키를 하나씩 가진 11-of-15 멀티시그. 정족수(11) 이상 담합·장애 시 자금 위험. 2026년 9월 사고처럼 키가 안전해도 검증 소프트웨어(Elements) 결함으로 담보가 빠질 수 있다 |
| 3. 데이터 가용성 | 각자 최신 상태 보관 (백업 주의) | 공식 문서로 확인 (사이드체인 블록 데이터를 누가 보관·공개하는가) |
| 4. 블록 생성·순서 | 해당 없음 (비트코인 블록) | 사이드체인 블록도 페더레이션 기관들이 서명해서 만든다 → 블록 생성·검열 권한이 페더레이션에 있다 |
| 5. 업그레이드 권한 | 구현체·사양 업데이트, 채널별 선택 | 공식 문서로 확인 (Elements 소프트웨어 변경 결정 주체, 사용자 탈출 시간 여부) |
| 6. 토큰 의존 | 없음 | 대응 자산 L-BTC는 페그된 BTC에 대한 청구권. 별도 토큰 가치가 보안에 필요한지는 공식 문서로 확인 |

현재 운영 상태: 2026년 9월 6일 Elements 결함으로 담보 없는 L-BTC가 유효한 페그아웃으로 처리되어 준비금 약 4,200 BTC 중 약 3,998.5 BTC 유출. 약 3,400 BTC 반환, 나머지는 Blockstream이 1:1 페그 보전 약속. 9월 중순 기준 블록 생성은 재개, 페그인·아웃 중단.

결론: 라이트닝은 상대가 협조하지 않아도 직접 온체인으로 정산할 권리가 있어(대신 온라인·감시 의무) 스펙트럼의 오른쪽, Liquid는 정족수의 정직과 검증 소프트웨어를 믿어야 하는 페더레이션이다. "누가 키를 갖나"만이 아니라 "누가, 어떤 소프트웨어로, 무엇을 검증하고 서명하나"까지 물어야 한다.
