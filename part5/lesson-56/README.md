# lesson-56 · 13-4 BitVM과 비트코인 롤업, 13강 미니 과제

## 목표
- BitVM이 Script로 계산의 "틀림"을 검증하는 원리를 개념 수준에서 설명한다 (s134-bitvm).
- BitVM 계열 브리지가 줄인 신뢰 가정과 남은 신뢰 가정을 설명한다 (s134-bitvm2).
- 비트코인 L2 주장을 체크리스트로 평가한다 (s134-checklist, s134-lab).

이 차시의 실습은 코드가 아니라 **문서 평가 과제**다(슬라이드에 코드 실습 없음).

## 정리
문제(s134-problem): 이더리움 롤업은 L1 컨트랙트가 증명을 검증하고 출금 조건을 강제한다. 비트코인 Script는 반복문도 상태도 없어(6-1) 임의의 계산 결과나 영지식 증명을 직접 검증할 수 없다 → 비트코인 L2의 출금은 대개 누군가(페더레이션, 운영자)의 서명에 기댄다.

BitVM(2023)의 낙관적 검증: "계산이 맞는지 증명하지 말고, 틀렸을 때 그걸 지적할 수 있게 하자"
1. 주장 — 운영자가 "결과는 X"라고 주장하고 담보를 건다
2. 이의 제기 기간 — 누구든 이의 제기
3. 챌린지 — 계산을 잘게 쪼개 어느 단계에서 틀렸는지 온체인에서 하나씩 확인(각 단계는 Script로 검증 가능한 작은 연산)
4. 결과 — 틀리면 담보 몰수·출금 차단, 이의가 없으면 주장대로

모든 경로를 미리 서명된 트랜잭션들과 Taproot 스크립트 트리(6-5)의 수많은 리프로 미리 구성한다.

| | 내용 |
|---|---|
| 줄어든 신뢰 | BitVM2 등은 누구나 챌린저(허가 없는 이의 제기). 페더레이션은 정족수의 정직, BitVM 브리지는 참여자 중 정직한 1명(1-of-n) |
| 남은 신뢰와 비용 | 운영자 출금 검열, 운영자가 미리 유동성을 대는 자본 비용, 챌린지 시 온체인 비용, 복잡한 구현의 버그 위험 |
| 실제 사례 | Bitlayer BitVM Bridge: 2025년 7월 출시 → 2026년 5월 "아키텍처 재구축"을 이유로 입금 중단, 6월 출금 창구 종료, 재개 일정 없음. 그 뒤에도 웹 화면은 정상처럼 보였다는 보도 → 평가는 마케팅이 아니라 현재 상태와 공식 공지로 |

신뢰 가정 스펙트럼(s134-spectrum): 단일 수탁(1명을 믿음) → 페더레이션(정족수) → BitVM 계열(1-of-n 정직) → 라이트닝(자기 감시) → 온체인 직접 보관(나만 믿음). 코버넌트(OP_CAT, CTV 등, 14-2)가 생기면 출금 조건을 더 직접 강제해 브리지·롤업 설계가 단순해질 수 있다는 주장과, 현재 Script로도 가능하니 합의 변경은 신중해야 한다는 입장이 있다.

## 과제 순서 (s134-lab)
1. 관심 있는 비트코인 L2 프로젝트 하나를 고른다.
2. 공식 문서만으로 체크리스트 6개 항목을 채운다.
3. 답을 찾을 수 없는 항목은 "문서에 없음"으로 표시한다.
4. 현재 운영 상태(입출금 가능 여부, 최근 공지)를 함께 기록한다.

"문서에 없음" 자체가 중요한 평가 정보다. 13-3 `reserve_check.py`로 공시 보유 주소를 직접 확인할 수 있으면 함께 적는다.

## 흔한 오해 (s134-myth)
- 비트코인 L2는 모두 비트코인 보안을 상속한다 → 대부분 별도의 수탁·합의에 기댄다.
- BitVM이면 신뢰가 전혀 필요 없다 → 운영자 검열, 자본 비용, 구현 위험이 남는다.
- 롤업이면 무조건 안전하다 → 비트코인 L1은 증명을 직접 검증하지 못해 보안 모델이 이더리움과 다르다.
