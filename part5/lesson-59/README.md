# lesson-59 · 14-3 프라이버시와 양자내성

## 목표
- 주소 재사용 문제와 Silent Payments(BIP352)의 원리를 설명한다 (s143-sp).
- 양자 컴퓨터가 위협하는 부분과 상대적으로 안전한 부분을 구분한다 (s143-threat).
- BIP-360을 중심으로 한 양자내성 대응 논의와 쟁점을 설명한다 (s143-exposure).

오늘의 프라이버시와 미래의 보안, 둘 다 "공개키가 언제 드러나는가"라는 같은 축 위에 있다.

Silent Payments: 고정 주소, 매번 다른 출력
1. 받는 사람 — `sp1` 주소 하나(스캔 공개키 B_scan + 지출 공개키 B_spend)만 공개
2. 보내는 사람 — 자기 입력 개인키 a로 S = a·B_scan → 출력 키 P = B_spend + Hash(S, k)·G (새 Taproot 출력)
3. 받는 사람 — Taproot 출력이 있는 트랜잭션마다 입력 공개키 A로 S = b_scan·A → 같은 P가 나오는지 확인

장점: 일반 Taproot 송금과 구분 불가, 받은 출력끼리 연결되지 않음, 사전 연락 불필요. 비용과 현황(2026년 7월): 모든 후보 트랜잭션을 스캔해야 해 계산 비용이 큼, 보내기는 18개 이상 지갑이 지원·받기는 소수, Core는 암호 모듈만 병합·지갑 기능은 미출시.

기타 도구(s143-tools, 사실 중심): PayJoin(BIP77 등, 받는 사람도 입력을 보태 공통 입력 휴리스틱을 깨뜨림), 코인조인(2024년 6월 한 코디네이터 서비스 중단, 2025년 11월 미국에서 다른 코인조인 지갑 공동 창업자 2명에게 징역 5년·4년 선고 — 무허가 송금업 공모), 라이트닝(결제가 체인에 기록되지 않음, 노드·채널 단위 노출은 존재). 프라이버시 기술의 존재가 곧 불법은 아니며, 분석하는 쪽은 그 한계와 가능성을 함께 알아야 한다.

양자 위협의 범위(s143-threat)
| 대상 | 양자 알고리즘 | 영향 |
|---|---|---|
| 타원곡선 서명 (ECDSA, Schnorr) | 쇼어 | 공개키에서 개인키 계산 가능 → 치명적 |
| 해시 (SHA256, RIPEMD160) | 그로버 | 보안 강도 약 절반 → 상대적으로 제한적 |
| 작업증명 | 그로버 | 이론적 이점, 실용성은 논쟁 중 |

| 출력 유형 | 공개키 노출 시점 | 양자 노출 |
|---|---|---|
| P2PK (초기 코인, 1-3) | 받을 때부터 | 노출 |
| P2PKH·P2WPKH (재사용 안 함) | 쓸 때 | 쓰기 전엔 해시 뒤에 |
| 재사용된 주소 | 한 번 쓴 뒤부터 | 노출 |
| P2TR | 받을 때부터 (출력키 = 공개키, 6-4) | 노출 |

노출 규모(Glassnode): 유통량의 약 30% = 구조적 노출 약 192만 BTC(P2PK·레거시 멀티시그) + 주소 재사용 노출 약 412만 BTC. 실용적 양자 컴퓨터 시점은 단정하지 않는다. 대응 논의: BIP-360(P2MR, 키 경로를 없앤 Taproot 변형, 2026년 2월 BIP 저장소 병합·초안·활성화 논의 전), BIP-361(기존 서명 유형 단계적 일몰, 2026년 4월 공개, 논쟁 중), 양자내성 서명 opcode(연구·시제품). 최대 쟁점: 움직이지 않는 노출 코인 — "동결해야 공격자에게 안 넘어간다" vs "누구의 코인도 프로토콜이 동결해선 안 된다".

## 기대 출력 (직접 실행해 확인 · 키가 매번 새로 만들어지므로 마지막 줄의 값은 실행마다 다름)
```
True
True
다른 a로 보낸 두 출력이 다르다: True
두 출력의 x좌표 앞 8바이트: 56b3729b4896dc20 50a659cc2da51656   (실행마다 다름)
```
- 첫 `True`: 받는 사람이 b_scan·A로 계산한 출력이 보내는 사람의 P와 같다. a·B_scan = b_scan·A (디피-헬먼)가 원리의 전부다.
- 둘째 `True`: 개인키 (b_spend + t2) mod N으로 P를 만들 수 있다 → 받는 사람만 쓸 수 있다.
- 이 단순화는 실제 BIP352와 다르다: input_hash(입력 아웃포인트·입력 공개키 합의 해시)를 곱하지 않고, 공유 비밀을 33바이트 압축 형식이 아니라 x좌표 32바이트로 해시하며, 레이블이 없다. 그래서 이 코드의 출력은 BIP352 테스트 벡터와 일치하지 않는다(ERRATA.md).

## 흔히 막히는 지점
- `ImportError: N` — `lib/ec.py`의 상수 이름은 `N`(곡선 위수)과 `G`. `point_mul(점, 스칼라)` 순서(점이 먼저).
- `% N`을 빠뜨리면 t가 위수보다 클 수 있다(확률은 무시할 만큼 작지만 규칙대로 줄인다).
- "Taproot이 양자에 더 안전하다"는 오해 — 출력키가 곧 공개키라 받는 순간부터 노출된다. BIP-360이 키 경로를 없애려는 이유다.
